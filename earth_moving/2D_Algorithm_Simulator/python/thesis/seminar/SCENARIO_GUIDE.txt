Each material entry is [x cell index, y cell index, number of objects].
For grid_size 22, indices run from 0 to 21. A pile at [8,3,5] occupies cell
(8,3), is drawn at its center (8.5,3.5), and contains five objects. Add or remove
entries to add or remove piles; do not duplicate cell coordinates. x increases
rightward and y upward in these exported figures. The older Pygame window uses
screen coordinates with y increasing downward; do not compare orientations
without accounting for this difference.

The target center/radius are continuous grid coordinates, not cell indices:
  "target": {"center": [9.5, 19.5], "radius": 2.0}
For your first changes, keep the target inside the grid and away from the two
selected source cells. It must contain at least one cell center. Keep JSON
commas between entries but no trailing comma after the final entry.

If you move the action pile, change action_source to its new [x,y] too. Likewise
focus_source must remain an occupied cell outside the target. The action source
needs a valid route: a high-heat source may have no highway connector. An error
then means choose another source or use action_type "target"; it does not mean
you should disable the verification checks.

Yes: the figure generator is separate from the rover application. It runs the
real 2D planner headlessly. It does not run a physics mission or invent heat.

Start with scenarios/corridor.json. Copy it under another name before editing.
Change material entries [x,y,count], grid_size, target center/radius, focus_source
(the source whose successor cone and main route are explained), action_source,
and planner parameters. action_type can be highway or target. Choose an occupied
source with an actual path. The generator uses the saved spillage setting (off when omitted). Its last
panel separately evaluates the source's target route using the configured
coefficient and threshold (defaults .05 and .03).

From PowerShell in this folder:

For the .cmd launcher, pass a python.exe path as the third argument to choose
a different environment. The .ps1 alternative accepts -Python but requires
PowerShell script execution to be allowed. The .cmd launcher requires no
PowerShell execution-policy change. Required libraries:
numpy, scipy, shapely and matplotlib. The launcher supplies the Windows conda
library path for this process. No package installation is performed.

Outputs include nine PNG/SVG pairs, example_data.json and planner_log.txt.
The JSON contains inputs, selected routes, headings, heat values before/after,
spillage outputs, source hashes and a comparison with a fresh recalculation.
The comparison checks material, heat, target AND highway routes, yields,
distances and headings for occupied non-target sources. It fails generation
if they disagree. A failure on another configuration is a diagnostic, not a
reason to silently replace selective results with a fresh calculation.

The original corridor example still uses an empty staging destination. The
occupied_destination example now conserves 16 objects and matches a fresh
recalculation, using 2 target searches instead of 4. Its spillage illustration
also predicts one deposited object and six at the target endpoint. These are
model outputs, not measured rover outcomes.
