2D algorithm simulator — intuition and mathematics

← Quick user guide · Implementation scope: current root Hybrid Orchestrator/env.py and search.py, with spillage_model.py. This describes implemented behavior, not a proof of globally optimal planning.

1. From material to opportunities

A target-delivery push collects material along a route. A staging push places material on a corridor that may support a later collection. The representation provides candidate actions before choosing a rover or a mission-level objective. Heat is a directional opportunity score; it is not local mass, travel time or guaranteed benefit.

For cell i, let pᵢ=(xᵢ+½,yᵢ+½), nᵢ its object count, T the target polygon, bᵢ a nearest point in T, and dᵢ=‖bᵢ−pᵢ‖. The simulator uses discrete counts and grid units, not calibrated mass or meters. Target membership tests cell centers.

2. Target visibility: possible next collection steps

An occupied non-target cell j is a successor of source i when it passes all three tests:

(pⱼ−pᵢ) · (bᵢ−pᵢ) ≥ ‖pⱼ−pᵢ‖ dᵢ cos θᵢ    [cone]
dⱼ ≤ dᵢ                                                    [progress]
‖pⱼ−pᵢ‖ ≤ g dᵢ                                           [range gate]

θᵢ is a half-angle. g is Visibility range factor. In fixed mode use the configured Target angle; in dynamic mode:

θᵢ = θmin + (θmax−θmin) [1 − min(dᵢ / D, 1)]
D = grid diagonal

If no occupied successor exists, the code adds a verified inside-target terminal. The cone drawn by the UI shows angular/range geometry; the complete successor rule also applies progress and occupancy. The fixed Target/Staging angles are ignored while dynamic mode is active.

3. Candidate routes and reuse of continuations

Target search orders states by collected reward plus a continuation heuristic. It rejects revisited cells and limits charged route length L to λdₛ, where s is the starting source and λ is Path length factor. The final edge is charged to the target boundary; the drawn polyline ends at an inside-target cell center. Do not identify these two lengths.

Q(P) = Σ nᵢ over distinct non-target cells on P
No-spillage ranking: maximize Q(P), then minimize L(P)
Spillage ranking: maximize predicted endpoint yield, then minimize L(P)

The visible-count heuristic is a local sum; memoized raw continuations are used only when they would already be available in a near-to-far full build. Processing and tie-breaking are deterministic. The search keeps a best collected count per cell, not a complete resource-state frontier. Candidate pruning, length caps and suffix stitching do not establish global optimality.

Spillage ranks returned candidates after search; it does not generate all possible spillage-optimal routes. Solved raw continuations are not reused in spillage mode.

4. Propagated value and heat

For each selected source path, propagate its raw candidate value through the path using a maximum. Let ψᵢ be the resulting value at i and vᵢ the normalized first-step direction of i’s selected target path. In spillage mode, the maximum raw candidate value and the retained-yield-selected route can come from different candidates; ψ is therefore not always the exact raw count along that selected route.

uᵢₓ = (pₓ−pᵢ) / ‖pₓ−pᵢ‖
Hincoming(x) = max over eligible i of ψᵢ [max(0, vᵢ·uᵢₓ)]ᵖ
H(x) = max(w Hown(x), Hincoming(x))

w is Own-path heat weight; p is Alignment exponent. The own component is seeded with the propagated ψ at an occupied source, not necessarily that source’s unpropagated route yield. At w=0 an upstream source can be cold even when its route is valuable. Contributions are maximized, not added, to avoid summing overlapping route values.

Eligibility excludes target cells, self-contributions, zero directions and nonpositive values. With rₓ=(pₓ−bₓ)/‖pₓ−bₓ‖, the radial gate requires rₓ·(−uᵢₓ) > cos γ, where γ is Heat radial gate. A further first-child distance cutoff limits the source’s reach. That child is stored during path propagation and can come from a contributing path. There is no continuous inverse-distance decay multiplier.

Increasing p suppresses imperfect alignment. Decreasing γ rejects more target-relative contributions. Neither parameter changes the material counts. Values are rebuilt from all retained paths after an action, because max accumulation alone cannot remove an obsolete contribution.

5. Staging anchor selection and paths

A source is considered for staging only when H(s)<βHmax. Anchors must satisfy H(a)≥αHmax and ‖pₐ−pₛ‖≤dₛ. α is Anchor min heat ratio; β is High-heat threshold. The chosen anchor maximizes:

Score(a | s) = wH H(a)/Hmax + (1−wH) [1−‖pₐ−pₛ‖/dₛ]

The editor sets distance weight to 1−wH. This is an anchor score, not the final mission objective. After selecting the anchor, staging search generates collection routes toward that same anchor. At every expanded node it builds anchor-specific successors using the staging cone, no-overshoot distance and strict progress toward the anchor; the anchor itself is always included. Dynamic staging angles use distance to that anchor in the same interpolation as above. The target-path length-factor control is not currently passed as a staging-search cap.

The repaired search does not use another source’s cached visibility toward a different anchor. Old staging results are cleared before global reconstruction, including sources that no longer qualify.

6. Spillage as a replaceable estimator

The current implementation smooths route waypoints into a spline and typically samples it 1000 times. It collects a supplied cell’s objects once on entering that cell. Let mₖ be carried load after pickup and κₖ the sampled curvature:

candidate loss ℓₖ = min(mₖ, a κₖ mₖ)
if ℓₖ ≥ ε: deposit ℓₖ at the sample cell and set mₖ ← mₖ−ℓₖ
otherwise: ignore that sample’s loss

a is Spillage coefficient and ε is Minimum spill. Remaining load is deposited at the endpoint, and deposits are rounded with conservation correction. Material already inside the target is excluded from pickup and new-delivery estimates, and preserved during execution.

The model has no arc-length/time-step normalization and its fallback curve has artificial curvature. It is resolution-sensitive, uses only supplied route-cell material rather than a swept shovel footprint, and does not enforce the capacity argument. Endpoint conservation correction can mask a spline missing a supplied cell. The alternative advisor branch is a zero-spillage placeholder.

A replacement should preserve the contract: route and material state in; predicted per-cell deposits, endpoint yield and input total out. Define units, capacity, footprint and conservation, and validate against observed rover pushes. Changing the estimator requires refreshing route predictions.

7. What “affected” must include

Changing one cell can alter a route several visibility edges upstream, even if the changed cell was not on the old best route. Direct observers alone are insufficient. The update takes touched non-target cells and forms a conservative reverse dependency closure:

A₀ = directly affected occupied sources plus direct observers
Aₖ₊₁ = Aₖ ∪ {s : s can depend on some cell in Aₖ}
stop when Aₖ₊₁ = Aₖ

The implementation uses old visibility edges plus current geometric tests, so it can detect both disappearing material and newly occupied cells. It invalidates solved flags and refreshes visibility/target searches only for the affected occupied sources. Emptied cells are marked but do not need a new source search.

  1. Update material and tracking.
  2. Find the reverse dependency closure; refresh affected source visibility.
  3. Recompute affected target routes in the same near-to-far order as a fresh build. Retain other source paths.
  4. Reset and regenerate propagated values/child links from all retained paths; update affected headings.
  5. Recompute heat over the grid and staging paths globally.

Thus “only affected target paths are updated” is an accurate statement about the search stage, not about every computation. Finding dependencies, repropagating values and rebuilding heat all cost work. In dense dependency graphs nearly all sources can be affected. No fixed speedup follows from this mechanism alone.

8. Verification and the seminar claim

The editor additionally rebuilds the same post-action material from scratch and compares material, heat, target/staging paths, yields, charged distances, headings, propagated components, anchors and predicted deposits. If it disagrees, the UI reports the failure and uses the full state. This verification intentionally prevents interpreting editor runtime as selective-update performance.

The regression suite exercises target/staging sequences on the 55-object layout and heavier pile counts, spillage on/off, fixed/dynamic visibility, moved targets and changed heat/range settings. It checks conservation and also verifies that unselected target-path objects are actually retained. See research/selective_update_20261114/validation.json for the executed count and per-action search counts. Finite checks are evidence, not a proof for every scene or parameter combination.

Suggested seminar wording: “After material moves, we update the target paths whose dependencies may have changed and reuse the others. The derived field and staging candidates are refreshed. Here the selective result is checked against a fresh calculation.” Report the displayed counts for the actual example; do not reuse an old speedup figure.

9. Parameter reference and limits

ParameterDefault demoMeaning / what changing it does
Target angle45°Half-angle of the target-facing visibility cone. Larger values admit more sideward candidates. Used only in fixed mode.
Staging angle60°Half-angle toward the chosen staging anchor. Larger values admit more detours toward that anchor. Used only in fixed mode.
Dynamic min angle30°Lower bound for the distance-dependent angle. Farther sources receive narrower cones.
Dynamic max angle60°Upper bound for the distance-dependent angle. Nearer sources receive wider cones. The editor keeps min ≤ max.
Visibility range factor1Limits target successor distance to this factor times distance to the target boundary. Smaller values shorten connections; the terminal fallback still exists.
Path length factor2Maximum charged target-route length relative to straight distance to the target. Larger values permit longer collection routes. This control does not currently cap staging-route search.
Own-path heat weight0Weights the occupied source’s own heat component. At 0, heat comes only from other sources. Increasing it can make more occupied sources exceed the staging threshold.
Alignment exponent1Raises positive directional alignment to this power. Above 1 suppresses off-axis heat; below 1 spreads it more broadly.
Heat radial gate75°Target-relative angular rejection gate for a heat contribution. Smaller angles reject more contributions before alignment is evaluated.
Anchor min heat ratio0.30A staging destination must reach this fraction of the map’s maximum heat. Increasing it restricts anchor candidates.
High-heat threshold0.50Sources at or above this fraction of maximum heat are skipped by staging-path construction. Increasing it makes more sources eligible for staging.
Heat weight0.70Balances anchor heat against proximity. The editor sets distance weight to 1 minus this value. It affects anchor choice, not target-route reward.
Spillage coefficient0.05Multiplies curvature and current load in the approximate spill model. Higher values tend to increase predicted losses, with threshold and rounding effects.
Minimum spill0.03Loss below this per-sample threshold is ignored. Increasing it suppresses small predicted deposits. It is not a geometric distance or a material fraction.

Scene size, target center/radius, material coordinates and counts are inputs rather than optimization weights. UI display switches do not stop the internal calculation. Heat colors auto-rescale in Pygame; exported static examples use a common before/after scale. Later rover control, task allocation and lookahead settings are separate from these 2D parameters.
