Start 2D Algorithm Simulator.exe. Default: 25×25 grid, 55 objects, seed 31, circular target centered at (12,12), radius 3. Coordinates increase rightward and downward, as in the original Pygame demo. The current planner runs on the old demo layout.

Try this demonstration

Display > groups the visual layers; Parameters > changes the algorithm. Scope lines OFF hides straight successor connections while retaining the cone and successor circles. In Move piles mode, clicking an empty cell clears the selected preview without editing the scene.

For the rehearsed seminar sequence, use 2D Algorithm Simulator.exe and the six-minute cue sheet and backup images.

  1. Open Display and click Visibility only, then select piles to explain which occupied cells they can see toward the target.
  2. Reveal Paths, then Vectors, then Heat. Vectors are directions, not speeds.
  3. Return to Scene controls, select a pile, choose T (target) or H (staging), and press Enter.
  4. In Display, turn Updates ON. This also turns unchanged-source outlines OFF. Explain the affected set and compare the displayed selective/full counts.
  5. Use U to undo, or S to save JSON, screenshot and a log in Saved Scenarios (beside the executable).

Drag piles to move or merge them. Add/Erase modes edit cells; the mouse wheel changes counts. In Move target mode, drag/click to move the circle and scroll to resize it. Edits and parameter changes rebuild the map. Reset restores the scene opened at startup. L loads the latest saved scene.

What the colors mean

  • Green filled circles: ordinary piles, not affected-cell highlights.
  • Pink E border: a cell became empty.
  • Cyan D border: an occupied cell’s material changed.
  • Yellow R border: an upstream source requires a target-path search because of a dependency.
  • Purple S border: a predicted non-endpoint spill deposit. This may overlap D.
  • Unchanged ON: optional green U borders on sources skipped by selective target searches. Keep this OFF for an affected-only demonstration.

Scope cycles selected/all/off; white or blue lines show actual successor connections, not affected cells. Paths cycles selected/all/off. All display switches leave internal planning results intact.

Parameters

Open Parameters and use +/−. These are the original-demo defaults; a loaded JSON scene can use different values. Scope switches target and staging visibility together between fixed and dynamic.

ParameterDefault demoMeaning / what changing it does
Target angle45°Half-angle of the target-facing visibility cone. Larger values admit more sideward candidates. Used only in fixed mode.
Staging angle60°Half-angle toward the chosen staging anchor. Larger values admit more detours toward that anchor. Used only in fixed mode.
Dynamic min angle30°Lower bound for the distance-dependent angle. Farther sources receive narrower cones.
Dynamic max angle60°Upper bound for the distance-dependent angle. Nearer sources receive wider cones. The editor keeps min ≤ max.
Visibility range factor1Limits target successor distance to this factor times distance to the target boundary. Smaller values shorten connections; the terminal fallback still exists.
Path length factor2Maximum charged target-route length relative to straight distance to the target. Larger values permit longer collection routes. This control does not currently cap staging-route search.
Own-path heat weight0Weights the occupied source’s own heat component. At 0, heat comes only from other sources. Increasing it can make more occupied sources exceed the staging threshold.
Alignment exponent1Raises positive directional alignment to this power. Above 1 suppresses off-axis heat; below 1 spreads it more broadly.
Heat radial gate75°Target-relative angular rejection gate for a heat contribution. Smaller angles reject more contributions before alignment is evaluated.
Anchor min heat ratio0.30A staging destination must reach this fraction of the map’s maximum heat. Increasing it restricts anchor candidates.
High-heat threshold0.50Sources at or above this fraction of maximum heat are skipped by staging-path construction. Increasing it makes more sources eligible for staging.
Heat weight0.70Balances anchor heat against proximity. The editor sets distance weight to 1 minus this value. It affects anchor choice, not target-route reward.
Spillage coefficient0.05Multiplies curvature and current load in the approximate spill model. Higher values tend to increase predicted losses, with threshold and rounding effects.
Minimum spill0.03Loss below this per-sample threshold is ignored. Increasing it suppresses small predicted deposits. It is not a geometric distance or a material fraction.

Spillage ON uses the current curvature estimator for route ranking and predicted deposits. Switching it OFF does not undo an earlier deposit; use Undo. It is not physical simulation, and the active model does not enforce capacity.

What is recomputed?

After an action, target searches run for the changed sources and their transitive dependencies. Cached target paths elsewhere are retained. Propagated values, heat and staging paths are rebuilt globally. The editor additionally runs a full calculation to check agreement, so its elapsed time is not a selective-update benchmark.

If verification fails on an untested scene, the editor says so and displays the full rebuild. Do not describe that action as a verified selective-update result. A smaller affected set is useful evidence of reduced search work, not by itself a measured speedup.
